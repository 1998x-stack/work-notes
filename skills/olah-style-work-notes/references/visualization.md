# Olah 式工作视觉文章规范

## 先问问题，再选图

- 顺序关系：带明确日期/区间的时间轴。
- 选择过程：决策树，分别标出备选项、约束、仍待确认条件。
- 多人协作：角色/职责图，但只能放已知明确角色。
- 系统理解：流程与依赖图，反映真实调用或信息流。
- 复盘问题：原因/影响/下一步的因果假设图，假设必须标注。
- 研究证据：观点与证据映射图，标明反例和证据缺口。

避免饼图百分比、工作效率评分、虚构指标和自称“精确预测”的无依据数字。

## 渐进式结构

第一屏给出最重要的事实/问题。第二屏建立背景。第三屏展示分歧或相互依赖。第四屏明确哪些结论已经形成、哪些仍未知。最后用简洁行动表收束。每张图只回答一个问题。

## SVG 与交互

独立 SVG 有 xmlns、viewBox、title、desc；内部 id 唯一，文字至少约 13px，色彩与线型双重编码，figure figcaption 说明图的洞察。可在交互中切换决策分支，但无 JS 也要看到完整默认解释。原生 button / aria-pressed 或 tab 状态、键盘焦点、prefers-reduced-motion、移动端溢出检查和打印样式均为验收项目。

## 来源展示

当图描绘的是建议而不是决定，要清楚使用“拟议”“假设”“待确认”等词，不因绘图视觉而升级为事实。
