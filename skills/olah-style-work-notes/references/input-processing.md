# 口述/ASR 的结构化处理

输入可能包含口头语、转写错误、说话人重叠、被省略的上下文、断裂的时间线。

1. 建立来源标识、录音/会议日期、转写来源和已知时区；无法确定则保留未知。
2. 纠正常见口头重复，但不能擅自替换组织名、技术名、数值和否定词。
3. 对每条原始观点标注 statement / proposal / decision / disagreement / open_question / action / editorial-synthesis。
4. 需要明示来源锚点：如说话片段时间戳或用户提供的原文段号；公开 evidence 仅可保留不敏感的引用标识，不把完整私有转写上传。
5. 决定需要明确的达成证据；“有人建议”不能自动变成“会议决定”。
6. 行动项的 owner / due_date / status 默认 unknown，原话未指定不得自动补全。
7. 使用两遍检查：第一遍面向事实保真，第二遍面向隐私与可发布性。若存在矛盾，标明待核对而非猜测。

输出的摘要必须让读者区分：事情发生了、有人提出了、团队决定了、准备去做、已经完成了。
